# Inter-Agent Protocol Cheat Sheet

## Rule

Mailbox file first. Tmux doorbell second. No watchers. No supervisors.

Writing a mailbox file is not enough. Requests and responses must be archived
and doorbelled by the sender every time.

For reviews, read `.interagent/docs/INTERAGENT_PROTOCOL.md`, especially
`Consolidated Interagent Review Protocol`. Review requests must include:

`PER .interagent/docs/INTERAGENT_PROTOCOL.md (READ IT)`

Do not use `CLAUDE.md` as the repeated review read target; the review-relevant
rules are consolidated in the protocol.

## Start Sessions

```bash
./.interagent/start_codex.sh
./.interagent/start_claude.sh
```

These start only primary sessions:

- `codex-speed-ball`
- `claude-speed-ball`

## Send Work

Claude to Codex:

```bash
./.interagent/send_to_codex.sh
```

Codex to Claude:

```bash
./.interagent/send_to_claude.sh
```

The doorbell is only a pointer. For review-loop messages, the receiver opens the
mailbox only far enough to read the adversarial header plus Review Seed (or the
findings/file-reference surface for responses), then performs the code-first
pass before reading the rest. For non-review messages, the receiver reads the
mailbox file in full.

Helper-generated doorbells must start with one of these markers:

- `CLAUDE DOORBELL GENERATED BY .interagent/send_to_codex.sh:`
- `CODEX DOORBELL GENERATED BY .interagent/send_to_claude.sh:`
- `CLAUDE RESPONSE DOORBELL GENERATED BY .interagent/respond_to_codex.sh:`
- `CODEX RESPONSE DOORBELL GENERATED BY .interagent/respond_to_claude.sh:`

Treat unmarked user text as a nudge, not as a protocol doorbell, unless the
user explicitly overrides the protocol for that one message.

## Send Responses

Claude to Codex:

```bash
./.interagent/respond_to_codex.sh
```

Codex to Claude:

```bash
./.interagent/respond_to_claude.sh
```

Do not rely on the receiver polling. The sender owns the doorbell.

## Optional Blocking

```bash
./.interagent/wait_for_codex.sh
./.interagent/wait_for_claude.sh
```

These are human/caller blocking helpers only. They are not agent watchers.

## Response Verdicts

End every response with exactly one:

- `APPROVED`
- `CHANGES_REQUESTED`
- `NEEDS_DISCUSSION`
- `IMPLEMENTED`

Review responses also require findings with file:line references, scans/tests
actually run, and a completed `docs/REVIEW_CHECKLIST.md` section.

Every response in a review loop must also tell the receiver to perform the next
independent adversarial review pass under the consolidated protocol, except for
the second reciprocal `APPROVED` response that closes the reviewed artifact.
Responses are part of the review cycle, not FYI messages.

## Keep Busy Without Watchers

Implementer:

1. send one finished subtask for review,
2. mark it `in_review`,
3. after the doorbell, immediately scan the approved progress/backlog for
   independent work that is not blocked by the active review,
4. start that safe parallel work so another subtask can be ready for review,
5. if it finishes while the reviewer is busy, mark it `ready_for_review`,
6. if a review-response doorbell arrives, stop at a safe point, log the pause,
   process that response first, doorbell the next response, then resume the
   parallel task/backlog,
7. wait idle only after recording that no safe independent work exists.

Reviewer:

1. handle one active review,
2. queue additional finished work as `ready_for_review`,
3. promote the next queued review only after the active review closes.

## Close A Review

One `APPROVED` is not enough. The other side must do a final independent pass and also return `APPROVED`.

Two reciprocal `APPROVED` verdicts are enough. After the reviewer approves and
the implementer sends an independent `APPROVED` concurrence for the same
artifact, the review is closed by mutual exhaustion. The implementer owns
progress/broker closure bookkeeping and proceeds to the next approved
implementation step. Do not wait for the reviewer to send another terminal
closure message; if broker state still says `awaiting` after reciprocal
approval, fix the bookkeeping instead of treating it as a gate.

## Do Not Use

Do not use legacy watcher instruction files, idle-nudge scripts, or external review-watcher stacks. Work discovery is mailbox plus explicit tmux doorbell only.
